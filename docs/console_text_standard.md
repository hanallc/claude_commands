# Console text standard

Use this standard for all text that Nate reads on the Console.

1. Start with the point. Use at most three sentences. Use Nate's words for his request or what he sees. State what he decides or learns.
2. Give only facts that can change his answer. State each fact once. Use at most three fact lines for a small yes or no.
3. Show the cause, the action, and the result. If Nate must act, say what the action changes in one line.
4. Give one recommendation when he must choose. Give the result he sees as the reason.
5. Describe what each thing does. Omit phase numbers, step letters, unit names, branches, files, test names, and run IDs.
6. Show one short command only when Nate must run it. Put it in backticks after the label `Run this command:`.
7. Put a number that affects the answer in the point or the first fact line. Give its unit.
8. Name a thing by where Nate sees it on the screen, for example "the round info icon on the rear panel of a tool". Do not use the name that the team gave it.
9. Do not give a behavior as a fact when Nate did not ask for it. Say that it is an addition, and give the choice to remove it.
10. Read the title and the point as a new reader. Check that the reader knows why the item exists and what each choice does.

## Example

### A test of the speech change needs you at the Mac for one minute

Hana now reads your speech from memory. You see the same result on the screen.
Before the change goes in, a Mac test asks you to permit speech.

1. If nobody accepts the macOS window in 30 seconds, the test fails.
2. Other work on the Mac continues during the test.

Run it (recommended because the speech change can go in) / Not now (the change waits and other work continues)

Tell the person who asked this question when you are at the Mac.
